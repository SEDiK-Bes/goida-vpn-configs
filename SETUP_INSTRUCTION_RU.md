### 1️⃣ GitHub Actions Workflows

В папке `.github/workflows/` находятся три рабочих файла:

#### frequent_update.yml
```
- Назначение: Частые обновления конфигов
- Расписание: Определено в файле (обычно каждые несколько часов)
- Действие: Запускает main.py и коммитит результаты
```

#### goida.yml
```
- Назначение: Основной workflow обновления
- Расписание: Определено в файле
- Действие: Основная логика обработки конфигов
```

#### update-configs.yml
```
- Назначение: Специализированное обновление конфигов
- Расписание: Определено в файле
- Действие: Дополнительная обработка
```

### 2️⃣ main.py

Основной Python-скрипт, который:
- Скачивает конфиги из источников
- Обрабатывает и очищает данные
- Удаляет дубликаты
- Добавляет SNI white-list
- Сохраняет результаты в githubmirror/all.txt

### 3️⃣ requirements.txt

Перечисляет необходимые Python-библиотеки:
- requests (для скачивания конфигов)
- И другие зависимости

GitHub Actions устанавливают зависимости автоматически при запуске.

## 🔧 КАК ВНЕСТИ ИЗМЕНЕНИЯ

### Сценарий 1: Хочу изменить расписание запусков

**Что делать:**

1. Открой файл одного из workflows (например, `.github/workflows/goida.yml`)
2. Найди строку `schedule:` с `cron:` выражением
3. Отредактируй расписание

**Пример текущего расписания:**
```yaml
schedule:
  - cron: '0 */6 * * *'    # Каждые 6 часов
```

**Примеры других расписаний:**
```yaml
'0 0 * * *'           # Каждый день в 00:00
'0 */4 * * *'         # Каждые 4 часа
'0 0 * * 0'           # Каждый понедельник в 00:00
'*/30 * * * *'        # Каждые 30 минут
```

**Шаг за шагом:**
1. GitHub → Repo → `.github/workflows/[имя].yml`
2. Нажми карандаш (Edit)
3. Найди `schedule:` → `cron:`
4. Отредактируй
5. Commit changes
6. Всё!

### Сценарий 2: Хочу отключить какой-то workflow

**Быстро:** Удали весь файл из `.github/workflows/`

**Аккуратно:** Добавь в начало файла строку:
```yaml
name: [Disabled] My Workflow
on: []  # Пусто = никогда не запускается
```

### Сценарий 3: Хочу изменить логику в main.py

1. Открой `main.py`
2. Отредактируй нужные части
3. Протестируй локально (если возможно)
4. Коммитни изменения
5. GitHub Actions подхватит новую версию при следующем запуске

### Сценарий 4: Хочу добавить новый источник конфигов

1. Открой `main.py`
2. Найди список источников (обычно в начале или середине файла)
3. Добавь новый URL
4. Коммитни

## 🐛 TROUBLESHOOTING

### Проблема 1: Workflow не запускается по расписанию

**Причины:**
- [ ] GitHub Actions отключены в Settings
- [ ] Расписание неправильное
- [ ] Синтаксическая ошибка в yaml
- [ ] Ветка не та

**Решение:**
1. Settings → Actions → General
2. Убедись что Actions включены
3. Проверь расписание (cron) в `.yml` файле
4. Используй YAML validator: https://www.yamllint.com/
5. Используй cron validator: https://crontab.guru/

### Проблема 2: Workflow выполняется, но падает

**Посмотри логи:**
- Actions → [workflow] → [run] → Logs

**Частые ошибки:**

```
ModuleNotFoundError: No module named 'X'
→ Решение: Добавь в requirements.txt: pip install X

ConnectionError: Failed to fetch...
→ Решение: Проверь доступность URL источников

PermissionError: Cannot commit
→ Решение: Проверь GitHub token в Settings → Secrets
```

### Проблема 3: Файл all.txt не обновляется

**Проверь:**
- Когда был последний запуск workflow?
- Может быть расписание очень редкое?
- Может быть скрипт падает с ошибкой?

**Решение:**
1. Посмотри размер файла all.txt (не должен быть 0)
2. Посмотри дату последнего обновления
3. Запусти workflow вручную (кнопка "Run workflow")
4. Посмотри логи
5. Если файл совсем пустой — проверь доступность источников
6. Если файл очень маленький — может быть фильтр слишком жёсткий

### Проблема 4: GitHub token проблема

**Ошибка:**
```
fatal: could not read Username for 'https://github.com':
```

**Решение:**
```yaml
# В workflow файле используй:
- run: git config --global credential.helper store
- run: echo "https://${{ secrets.GITHUB_TOKEN }}@github.com" > ~/.git-credentials
```
